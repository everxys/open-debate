# AI 辩论场 - 项目需求文档

## 项目概述

AI 辩论场是一个多 AI 辩论平台。用户创建多个 AI 配置，围绕一个问题按固定顺序轮流发言，实时查看进度，并在结束后复盘完整记录。

本文档以 `V1.0 MVP` 为主，所有超出 MVP 的能力都明确标记为后续版本，避免设计范围失控。

---

## V1.0 核心目标

1. 用户可以完成注册、登录、密码重置。
2. 用户可以创建并管理自己的 AI 配置。
3. 用户可以发起一场 2-5 个 AI 参与的辩论，并设置固定发言顺序与最大轮数。
4. 系统可以顺序执行辩论、记录每轮输出、支持暂停/恢复/停止。
5. 前端可以实时看到状态和发言更新。
6. 辩论结束后可以查看记录并导出 Markdown。

---

## V1.0 功能需求

### 1. 用户认证

- Supabase Auth 邮箱注册/登录
- 密码重置
- 登录后仅能访问自己的数据

### 2. AI 配置管理

- 创建/编辑/删除 AI 配置
- 支持 `OpenAI` 和 `Anthropic`
- 可配置字段：
  - 名称
  - provider
  - model
  - temperature
  - max_tokens
  - system_prompt
- API Key 仅后端可见，前端只显示脱敏值

### 3. 辩论创建

- 输入辩论问题
- 选择 2-5 个 AI
- 设置发言顺序
- 设置最大轮数，默认 10，最大 50
- 可选设置单场 token 预算

### 4. 辩论执行

- 系统按顺序轮流调用 AI
- 每轮保存原始文本和结构化结果
- 结构化解析失败时保留原始文本并标记解析失败
- 单轮失败最多重试 2 次
- 终止条件：
  - 达到最大轮数
  - 用户手动停止
  - token 预算耗尽
  - 命中简化共识条件

### 5. 简化共识

MVP 只保留轻量规则：

- AI 输出一个 `proposed_solution`
- AI 可输出 `support` / `rebuttal` 论据
- 系统仅按支持数、反驳数、最近同意度做基础判断
- 共识只作为“提前结束”机制，不承担复杂裁决功能

### 6. 实时控制台

- 实时显示辩论状态
- 实时追加发言流
- 显示当前轮次、参与者、token 使用量
- 支持暂停、恢复、停止
- 显示实时连接状态

### 7. 结果展示

- 查看完整发言记录
- 查看最终状态：完成 / 停止 / 失败
- 查看基础统计：总轮数、总耗时、总 token
- 导出 Markdown

## 非功能需求

| 类别 | 需求 |
|------|------|
| 性能 | 常规列表与详情页响应流畅，支持分页/增量加载 |
| 实时性 | 新发言到前端可见延迟目标 < 2 秒 |
| 安全 | API Key 不暴露前端；所有业务表启用 RLS |
| 容错 | AI 调用失败可重试；解析失败不应中断整场辩论 |
| 可观测性 | 记录请求失败、重试、耗时、token 使用量 |
| 成本控制 | 支持单场 token 上限，超限自动停止 |

---

## 明确不在 V1.0 的能力

以下功能保留到 V2.0 以后，不进入 MVP 设计、接口或数据库主流程：

- 动态加入 AI
- 多方案融合
- 用户投票 / 权重调整 / 裁判 AI
- 观点图谱与语义聚类
- 五维度高级共识算法
- 模板库、批量导入导出、团队协作
