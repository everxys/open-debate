# 四阶段推进规则（状态机 + 子任务）

目标不是让所有人一直泛泛讨论，而是让长轮次真正逐块推进创作圣经。

## 总推进铁律

- 当前策略采用：Phase > 子任务 > Round > Turn
- 一个阶段只解决一类核心问题
- 一个子任务只解决阶段中的一小块具体问题
- 一轮只推进一个子任务
- 一个回合只推进该轮中的局部结论
- 当前子任务没有清晰结论前，不允许横跳
- 当前阶段没有明显完成前，不允许提前进入收尾语气

如果 Host 没有明确宣布当前子任务，则默认按本文件给出的推荐顺序推进。

## Phase 1：议题定向与风险暴露

目标：
- 先把作品的方向、边界、风险和评价标准讨论清楚
- 让固定 Host 看清当前最值得推进的主问题

当前阶段严禁：
- 提前正式投票
- 假装已经进入点子筛选
- 急着写圣经细节、章节细纲、终局成稿

推荐子任务顺序：
1. 终极命题与故事承诺
2. 世界规则与底层限制
3. 这类题材最容易失败的地方
4. 当前最值得优先打磨的方向
本阶段最常见的伪推进：
- 看起来说了很多，但只是提前写圣经细节
- 把局部灵感误判成全书主线
- 还没定方向，就开始细写人物、事件或章节

Phase 1 的通过标准不是“大家都说得很热闹”，而是至少已经形成：
- 一条足够清楚的作品核心命题
- 一套初步可信的底层约束方向
- 一份明确的高风险失败清单

## Phase 2：动态轮换讨论

目标：
- 用长轮次分块构建完整创作圣经
- 不让讨论无限发散

Host 每轮必须宣布当前唯一子任务。若 Host 未宣布，默认按以下顺序推进：
1. 原始点子筛选与重组
2. 主线骨架与终局真相
3. 七位外来天才与本土天才生态
4. 五大核心事件
5. 人物弧线 / 纯爱线 / 背叛线 / 宿敌线
6. 终局布局链与伏笔回收
7. 分卷结构与长篇强度递增
8. 章节级展开

在 Phase 2 中，所有点子都应默认进入“大点子 / 中点子 / 小点子”分层处理：
- 大点子负责统治全书骨架
- 中点子负责驱动事件或主线
- 小点子负责二刷快感、记忆点和神来之笔
- 任何新点子都必须尽量说明自己属于哪一层、服务哪条主线、替代或强化了哪些旧方案

当前阶段严禁：
- 一轮同时大谈人物、终局、章节、事件、世界观
- 为了显得推进多而平铺很多点子
- 还没打稳当前块就急着写最终成稿

当前阶段的判断标准不是“这轮说了很多”，而是：
- 当前子任务是否真的比上一轮更稳定、更狠、更可复盘
- 是否形成了可落到文件里的结论
- 是否明确指出了当前最弱一笔

Phase 2 的最低产物不是热闹讨论，而是：
- 当前子任务至少已有一个稳定候选结论
- 这个结论已经能落到共享文件或最终交付文件
- 团队已经知道它最容易翻车的地方在哪里

## Phase 2.5：进入 Phase 3 前的正式表决

目标：
- 判断当前讨论是否已经具备收束资格

必须检查：
- 关键子任务是否已经达到可收束状态
- 是否仍存在结构性硬缺口
- 主要文件是否已具备被整合的前提
- 是否还有明显伪强内容、空泛内容、不可复盘内容

只有当大家都认为：
- 再继续 Phase 2 已很难产生结构性变化
- 现在的主要问题已经从“探索”变成“整合与校验”
才允许进入 Phase 3

本阶段最常见的伪推进：
- 只是讨论累了，就想提前进入收束
- 文件数量变多，就误以为已经成熟
- 局部有亮点，就误判为全局已稳定

## Phase 3：共识收敛与最终交付

目标：
- 不是继续泛讨论，而是整合、审查、补洞、回收、交付

当前阶段优先子任务：
1. 交付文件总检查
2. 当前最弱一笔清除
3. 伏笔与终局回收自检
4. 逻辑闭环与二刷成立性检查
5. 最终总汇总稿整合

当前阶段严禁：
- 回到大规模自由发散
- 用新设定掩盖旧漏洞
- 因为快结束了就降低质量标准

通过标准：
- 文件达到交付要求
- 主要矛盾有明确处理
- 终局能回看成立
- 监管者认可“没有明显伪强内容仍在裸奔”

Phase 3 的最低产物必须包括：
- 可交付文件已形成明确版本
- 当前最弱一笔已被正面处理，而不是被跳过
- 最终总纲不只是拼文件，而是真正形成统一口径

若仍出现以下问题，则不得结束：
- 关键事件只能靠解释成立
- 主要角色仍然像“不同版本的聪明人”
- 终局回收无法支撑二刷
- 最终总纲只是把文件拼在一起，没有真正形成统一口径
