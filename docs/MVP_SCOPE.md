# AI 辩论场 - MVP 范围定义

## 概述

本文档定义 AI 辩论场项目的最小可行产品（MVP）范围，明确 V1.0 必须实现的功能和后续迭代的优化项。

---

## 版本规划

| 版本 | 目标 | 预计周期 |
|------|------|----------|
| V1.0 (MVP) | 核心辩论功能可用 | 2-3 周 |
| V1.1 | 用户体验优化 | 1 周 |
| V2.0 | 高级功能 | 2-3 周 |
| V3.0 | 商业化功能 | 2 周 |

## V1.0 MVP 功能清单

### 必须实现（Must Have）

#### 1. 用户认证
- [ ] Supabase Auth 集成
- [ ] 邮箱注册/登录
- [ ] 密码重置

#### 2. AI 配置管理
- [ ] 创建/编辑/删除 AI 配置
- [ ] 支持 OpenAI 和 Anthropic 两家提供商
- [ ] 基础参数配置（temperature, max_tokens）
- [ ] API Key 安全存储（后端加密）

#### 3. 辩论创建与配置
- [ ] 输入辩论问题
- [ ] 选择 2-5 个 AI 参与者
- [ ] 设置发言顺序
- [ ] 配置最大轮数（默认 10，上限 50）

#### 4. 辩论引擎核心
- [ ] 按顺序轮流发言
- [ ] AI 发言结构化输出（JSON）
- [ ] 解析失败降级处理
- [ ] 基础重试机制（最多 2 次）

#### 5. 实时控制台
- [ ] 发言历史流展示
- [ ] 辩论状态显示（运行中/暂停/完成）
- [ ] 暂停/恢复/停止控制
- [ ] Supabase Realtime 实时更新

#### 6. 结果展示
- [ ] 辩论完成状态
- [ ] 发言记录查看
- [ ] 导出为 Markdown

#### 7. 数据存储
- [ ] debates 表：辩论会话
- [ ] ai_agents 表：AI 配置
- [ ] debate_agents 表：关联表
- [ ] debate_turns 表：发言记录

#### 8. 基础错误处理
- [ ] API 失败重试
- [ ] 网络错误提示
- [ ] 友好的错误信息

## MVP 成功标准

### 功能标准
- [ ] 用户可以完整创建并运行一场辩论
- [ ] 辩论至少支持 5 轮 x 3 AI
- [ ] 实时更新延迟 < 2 秒
- [ ] API 错误率 < 5%

### 用户体验标准
- [ ] 新用户 5 分钟内完成首次辩论
- [ ] 页面无明显卡顿
- [ ] 关键操作有明确反馈

### 技术标准
- [ ] 核心流程单元测试覆盖率 > 70%
- [ ] 关键 API P99 延迟 < 1s
- [ ] 服务可用性 > 99%

## MVP 开发优先级

```
第一周：
├── 项目脚手架搭建
├── Supabase 数据库设置
├── 用户认证集成
└── AI 配置管理（CRUD）

第二周：
├── 辩论引擎核心
├── 队列系统（Bull）
├── 实时控制台
└── 基础错误处理

第三周：
├── 结果展示页
├── 导出功能
├── 简化版共识检测
├── 测试与 Bug 修复
└── 部署上线
```

---

## 范围变更管理

任何 MVP 范围变更需满足以下条件之一：
1. 发现技术不可行
2. 用户测试反馈强烈需求
3. 发现重大安全漏洞需修复

变更流程：
1. 记录变更原因
2. 评估影响范围
3. 更新本文档
4. 通知相关人员
