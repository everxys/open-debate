# 工作流驱动的投票/角色方案（让项目通用）

## 目标
把“第几轮投票、要选哪些角色（主持人/监管员等）、投完是否调整发言顺序”等玩法规则从程序里移出去，改为由【策略】提供一份规则配置来决定。  
程序只保留通用能力：开始投票 / 投票 / 结束投票 / 保存官方结果 / （可选）按结果调整发言顺序。

这样：不同辩论只要换策略，就能换一套玩法；不需要主持人/监管员的辩论也能正常运行。

---

## 核心原则（最佳实践）
- **程序做“能力”**：提供可靠、可持久化、可展示的“官方投票”机制（开/投/关/保存结果），以及安全的“调整发言顺序”能力。
- **策略做“规则”**：是否启用投票、从第几轮开始、要选哪些角色、是否要求某角色必须第一/最后发言。

默认行为：**不启用投票/角色**，除非策略显式开启。

---

## 策略侧：规则配置文件
### 文件位置（约定）
在策略里增加一个文件：`debate/workflow.json`

创建辩论时：
- 如果策略存在该文件：复制到该辩论的“辩论文件”中，路径为 `workflow.json`
- 如果不存在：表示此策略不启用官方投票/角色（默认关闭）

> 注意：这是“策略文件”的一部分，不需要数据库改表。

### 配置想表达的内容（概念）
`workflow.json` 需要能表达：
1) 是否启用官方投票（enabled）
2) 从第几轮开始允许投票（startRound）
   - 例：前两轮不投票，则 startRound=3
3) 选举/投票要选哪些“角色”
   - 角色名是任意字符串，例如：["Host","Supervisor"] 或 ["Moderator","Judge"] 或空（不选角色）
4) （可选）发言顺序约束
   - 例：某角色必须每轮第一个发言、某角色必须每轮最后一个发言

---

## 程序侧：需要做的改造（只做通用能力）
### 1) 创建辩论时复制 workflow
当用策略创建辩论：
- 检查策略文件里有没有 `debate/workflow.json`
- 有就复制到辩论的 `workflow.json`（作为本场辩论的规则来源）
- 没有就不复制（本场辩论不启用官方投票/角色）

### 2) 官方投票能力保留，但必须受 workflow 控制
程序里的“官方投票”功能仍然存在，但要改成：
- 如果辩论没有 `workflow.json` 或其中 enabled=false：官方投票不可用
- 如果当前轮次 < startRound：官方投票不可用（从而实现“前两轮不投票”这类规则）
- 如果是“角色选举”：投票内容按 workflow 里声明的角色列表来投（不再写死只有主持人/监管员）

### 3) 官方投票结果保存为“机器可读 + 人可读”
结束投票后保存：
- “官方投票结果”（用于 UI 展示、后续追溯）
- “官方角色任命/指令”（如果本次是角色选举）

并且：
- 如果 workflow 里要求“某角色必须第一/最后发言”，在选举结果出来后生成“待应用的新发言顺序”
- 新顺序必须在“下一轮开始时”才自动生效（避免中途换顺序引发 bug）

### 4) UI 展示改为只看官方结果
- 右侧“投票结果”不再从 AI 发言里猜测/匹配
- 只展示程序保存的官方投票结果文件
- “应用官方顺序”也按 workflow 的约束来做（不再固定 Host/Supervisor）

---

## 验收标准（必须通过）
1) 用没有 `debate/workflow.json` 的策略创建辩论：
   - 不出现官方投票环节
   - 不出现角色任命
   - 不会自动调整发言顺序

2) 用带 `debate/workflow.json` 的策略创建辩论（示例：enabled=true, startRound=3, roles=["Host","Supervisor"]）：
   - 第 1~2 轮无法开启官方投票
   - 第 3 轮起可以开启角色选举并完成投票
   - 结束后 UI 能看到“官方投票结果”
   - 若配置要求 Host 第一、Supervisor 最后：下一轮开始自动调整顺序

---

## 推荐默认值（为了通用）
- 默认：没有 workflow 就等于关闭官方投票/角色
- 只有策略显式提供 workflow 才启用
- 角色列表任意，不强制一定有主持人/监管员
