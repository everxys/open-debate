# AI 辩论场 - 安全审计清单

## 概述

本文档聚焦当前技术栈下的 `MVP` 安全基线，优先覆盖认证、RLS、密钥保护、日志脱敏和速率限制。文档中的要求必须能在 `Next.js + Supabase` 架构中落地。

---

## 当前设计中需要纠正的点

1. 认证由 `Supabase Auth` 承担，不应再设计自建密码哈希、JWT 签发和 refresh token 撤销体系。
2. API Key 若存数据库，必须是应用层可解密密文；仅保存 `api_key_ref` 无法直接支撑运行时调用，除非已接入外部 KMS。
3. `X-XSS-Protection` 已过时，不应再作为现代浏览器主要防护手段。
4. 不能依赖“过滤 `< > ' \"`”来防 XSS，核心手段应是输出转义、白名单渲染和 CSP。
5. 对 Supabase 查询而言，`.filter(...)` 不等于 SQL 注入；真正风险是越权、错误拼接 RPC 或缺失 RLS。

---

## 1. 认证与会话

### MVP 要求

- 使用 Supabase Auth 邮箱登录
- 受保护接口必须校验当前会话
- 服务端只信任服务端获取的用户身份，不信任前端透传的 `user_id`
- 关键页面和 API 默认需要登录

### 检查项

- [ ] 所有业务接口都验证登录态
- [ ] 只使用 Supabase 官方推荐的会话校验方式
- [ ] 未登录访问返回统一 `401`
- [ ] 不在客户端持久化额外敏感凭证

---

## 2. API Key 管理

### MVP 要求

- API Key 不写入前端、不出现在浏览器网络请求体
- 由服务端持有并调用上游 AI API
- 数据库存储密文 + 掩码展示值
- 日志禁止记录明文 key

### 推荐实现

- 字段拆分：
  - `api_key_encrypted`
  - `api_key_masked`
- 使用 `AES-256-GCM`
- 主密钥来自环境变量或外部密钥管理服务

### 检查项

- [ ] 响应体中不返回明文 API Key
- [ ] 编辑页面只显示掩码值
- [ ] 保存新 key 时才更新密文字段
- [ ] 删除 agent 时同步清理相关敏感数据

---

## 3. 输入与输出安全

### 核心原则

- 结构化输入用 schema 校验
- Markdown 渲染采用安全白名单
- 不渲染 AI 返回的原始 HTML
- 导出内容默认作为文本处理

### 检查项

- [ ] 所有 API 输入使用统一 schema 校验
- [ ] Markdown 渲染禁用危险 HTML
- [ ] 错误消息不回显敏感内部信息
- [ ] 搜索、筛选、分页参数有边界限制

---

## 4. 授权与 RLS

### MVP 原则

- `debates`、`ai_agents`、`debate_agents`、`debate_turns` 全部启用 RLS
- 用户只能访问自己的资源
- 服务角色只在服务端后台任务中使用

### 检查项

- [ ] 所有业务表启用 RLS
- [ ] 通过 debate 归属链限制 turns 读取
- [ ] 创建辩论时校验所选 agent 全部归当前用户
- [ ] 更新 / 删除接口做资源归属校验

---

## 5. 速率限制与资源保护

### MVP 要求

- 认证接口限流
- 写接口限流
- AI 测试连接接口单独限流
- 单用户并发运行中的辩论数量有限制

### 检查项

- [ ] 登录/重置密码有频率限制
- [ ] 创建辩论和测试连接有更严格限制
- [ ] 超限返回 `429`
- [ ] 长时间运行的辩论有超时终止

---

## 6. 日志、监控与错误处理

### 要求

- 日志中脱敏：`apiKey`、`authorization`、`cookie`、`token`
- 生产环境错误响应不返回堆栈
- 记录 AI 调用失败率、重试次数、超时次数

### 检查项

- [ ] 统一错误码
- [ ] 生产环境不暴露 stack trace
- [ ] 敏感字段自动 redact
- [ ] 有失败率和异常增长告警

---

## 7. HTTP 安全头

### 建议配置

- `Content-Security-Policy`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Strict-Transport-Security`

说明：`X-XSS-Protection` 不再作为必配项。

---

## 8. 安全测试

- RLS 越权测试
- API 未认证访问测试
- API Key 不泄露测试
- Markdown/XSS 回归测试
- 依赖漏洞扫描

---

## 上线前最低安全门槛

- [ ] 所有业务表启用并验证 RLS
- [ ] API Key 仅服务端可见且数据库为密文
- [ ] 关键接口完成鉴权与限流
- [ ] 日志脱敏已验证
- [ ] 生产错误响应不泄露内部细节
