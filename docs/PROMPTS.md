# AI 辩论场 - 提示词模板

## 概述

本文档定义系统中使用的提示词模板。`V1.0 MVP` 只使用标准辩论提示词、上下文提示词和基础 UI 提示词；裁判 AI、方案融合、动态加入等段落仅作为 `V2+` 预留参考，不进入当前实现。

---

## 第一部分：辩论系统提示词

### 1. 系统提示词（System Prompt）

#### 1.1 标准辩论提示词

```
你是一个 AI 辩论参与者。请遵守以下规则：

1. 围绕问题 "{{question}}" 进行辩论
2. 每次发言必须以 JSON 格式输出，包含：
   - proposed_solution: 你支持的方案（简短名称）
   - arguments: 论据列表，每个论据包含：
     - type: "support"（支持）或 "rebuttal"（反驳）
     - content: 论据内容（1-3 句话）
     - strength: 强度（0.1-1.0）
     - target: 如果是反驳，指明反驳的对象

3. 保持逻辑清晰，避免重复已有观点
4. 如果同意某个方案，请在论据中明确表达

示例输出：
{
  "proposed_solution": "方案 A",
  "arguments": [
    {"type": "support", "content": "因为...", "strength": 0.8},
    {"type": "rebuttal", "content": "反驳...", "strength": 0.6, "target": "方案 B"}
  ]
}
```

#### 1.2 角色设定提示词（可选追加）

```
[角色设定]
你现在的身份是：{{role_setting}}
你的辩论风格是：{{style}}（正式/幽默/批判性/建设性）
你的立场倾向：{{stance}}（支持/反对/中立）

请以这个身份进行辩论，但保持逻辑严谨。
```

### 2. 用户提示词（User Prompt）

#### 2.1 首轮发言

```
辩论问题：{{question}}

这是第 {{turn_number}} 轮，你是第 {{agent_position}} 个发言的 AI。

之前已有的观点摘要：
{{context_summary}}

请发表你的观点。
```

#### 2.2 后续轮次发言

```
辩论问题：{{question}}

这是第 {{turn_number}} 轮，你是第 {{agent_position}} 个发言的 AI。

上一位 AI（{{previous_agent}}）的观点：
{{previous_content}}

当前方案池得分排名：
{{solution_ranking}}

请针对现有观点进行补充、支持或反驳。
```

### 3. 共识确认提示词

```
当前辩论已进行 {{turn_number}} 轮，方案 "{{solution_name}}" 目前得分最高。

请回答以下问题：
1. 你是否同意 "{{solution_name}}" 是当前最佳方案？（是/否/部分同意）
2. 请给出 0-10 的同意度评分
3. 如有保留意见，请说明理由

请以 JSON 格式回答：
{
  "agree": "yes/no/partial",
  "score": 8,
  "reason": "..."
}
```

---

### 4. 裁判 AI 提示词

```
你是一个中立的辩论裁判。请分析以下争议：

辩论问题：{{question}}
争议焦点：{{conflict_point}}

正方观点：
{{supporting_arguments}}

反方观点：
{{rebuttal_arguments}}

请从以下维度分析：
1. 逻辑一致性：哪方论证更严密？
2. 证据强度：哪方论据更充分？
3. 覆盖范围：哪方考虑更周全？
4. 可行性：哪方方案更可行？

请以 JSON 格式输出分析结果：
{
  "analysis": {
    "logic": {"winner": "support/rebuttal/tie", "reason": "..."},
    "evidence": {"winner": "...", "reason": "..."},
    "coverage": {"winner": "...", "reason": "..."},
    "feasibility": {"winner": "...", "reason": "..."}
  },
  "conclusion": "综合判断...",
  "recommended_action": "采纳正方/反方观点/继续辩论"
}
```

### 5. 协调者 AI 提示词（方案融合）

```
你是一个方案协调者。以下是当前得分最高的 N 个候选方案：

{{solution_details}}

请综合这些方案的优点，生成一个融合方案。要求：
1. 保留各方案的核心优势
2. 消除方案间的矛盾和冲突
3. 方案应具有可执行性
4. 输出为结构化 JSON

输出格式：
{
  "fused_solution_name": "融合方案名称",
  "description": "详细描述",
  "components": [
    {"source": "方案 A", "element": "核心要素", "adaptation": "如何适配"}
  ],
  "advantages": ["优势 1", "优势 2"],
  "potential_issues": ["潜在问题 1", "潜在问题 2"]
}
```

---

### 6. 上下文摘要提示词

```
以下是辩论历史记录（共 {{turn_count}} 轮）：

{{debate_history}}

请生成一个不超过 500 字的摘要，包含：
1. 已提出的所有候选方案
2. 每个方案的核心论据
3. 主要争议焦点
4. 当前共识状态

摘要应简洁明了，让新加入的 AI 能快速了解辩论进展。
```

---

### 7. 提示词变量说明

| 变量 | 说明 | 来源 |
|------|------|------|
| `{{question}}` | 辩论问题 | debates.question |
| `{{turn_number}}` | 当前轮次 | debates.current_turn |
| `{{agent_position}}` | AI 发言顺序 | debate_agents.turn_order |
| `{{context_summary}}` | 上下文摘要 | 由摘要 AI 生成 |
| `{{solution_ranking}}` | 方案得分排名 | scheme_scores |
| `{{role_setting}}` | 角色设定 | ai_agents.role_setting |
| `{{style}}` | 辩论风格 | 用户配置 |
| `{{stance}}` | 立场倾向 | 用户配置 |

---

### 8. 提示词最佳实践

#### 8.1 结构化输出保证
- 在提示词中明确输出格式
- 提供完整示例
- 要求 JSON 输出时指定 schema
- 设置 temperature 为 0.3-0.5 提高稳定性

#### 8.2 防止偏离主题
- 在提示词开头重申辩论问题
- 要求 AI 检查输出是否相关
- 设置"如果无法回答，请说明"的兜底逻辑

#### 8.3 控制输出长度
- 明确字数限制
- 要求简洁表达
- 过长输出可能被截断

#### 8.4 多语言支持
- 提示词语言与用户问题一致
- JSON 键名保持英文
- 内容支持中文/英文/日文等

## 第二部分：UI 生成提示词

### 基础约定

#### 技术栈

```
- 框架：Next.js 14+ (App Router)
- 语言：TypeScript
- UI 库：shadcn/ui + Tailwind CSS
- 图标：lucide-react
- 状态管理：React Query + Zustand
- 实时通信：Supabase Realtime
```

#### 设计系统

```
- 主色调：蓝色 (blue-600)
- 圆角：medium (rounded-md)
- 字体：Inter / system-ui
- 暗色模式：支持
```

### UI 生成提示词模板

#### 1. 配置向导页面

```
创建一个 AI 辩论配置向导页面，包含以下步骤：

**步骤 1：输入辩论问题**
- 大文本输入框（textarea）
-  placeholder："请输入要辩论的问题，例如：人工智能是否应该拥有法律人格？"
- 字符计数器
- 下一步按钮

**步骤 2：添加 AI 参与者**
- 显示已添加的 AI 列表（卡片形式）
- "添加 AI"按钮，打开对话框
- 拖拽排序功能（决定发言顺序）
- 每个 AI 卡片显示：名称、提供商、模型、状态
- 删除按钮
- 至少需要 2 个 AI 才能继续

**步骤 3：配置辩论参数**
- 最大轮数滑块（1-100，默认 10）
- Token 预算输入框（可选）
- 共识阈值配置（高级选项）
- 开始辩论按钮

**UI 要求**
- 使用 Stepper 组件显示进度
- 响应式设计
- 每步有上一步/下一步导航
- 使用 shadcn/ui 组件

**状态管理**
- 使用 useForm 管理表单状态
- 数据验证使用 zod
- 提交前校验所有必填项
```
