## 高优先级问题

### 1. 结构化输出可靠性

**状态**: 已识别 | **优先级**: P0

#### 问题描述
AI 可能不总是输出正确的 JSON 格式，导致解析失败。

#### 影响
- 观点提取失败
- 共识得分无法计算
- 辩论流程中断

#### 解决方案

**策略一：多重解析**
```
1. 尝试直接 JSON.parse
2. 失败则提取文本中的 JSON 块
3. 再失败则调用 AI 修复格式
4. 最后降级为非结构化模式
```

**策略二：Schema 验证**
- 使用 Zod 定义响应 schema
- 验证失败时触发修复流程

**策略三：预防**
- 提示词中提供完整示例
- 设置较低 temperature (0.3-0.5)
- 要求 AI 用 ```json 包裹输出

#### 详细实现
见 `IMPLEMENTATION.md` 第 1 节

### 2. 长辩论上下文爆炸

**状态**: 已识别 | **优先级**: P0

#### 问题描述
辩论轮数多时，上下文可能超出模型 token 限制。

#### 影响
- API 调用失败
- 新 AI 无法理解历史
- 成本急剧增加

#### 解决方案

**方案 A：滑动窗口**
- 保留最近 N 轮发言
- 始终保留首轮发言
- 可选包含摘要

**方案 B：摘要压缩**
- 每 10 轮生成一次摘要
- 摘要限制在 300 字以内
- 包含方案、论据、争议点

**方案 C：关键信息提取**
- 提取各方案核心要点
- 记录已达成共识
- 记录主要争议点

#### 详细实现
见 `IMPLEMENTATION.md` 第 2 节

### 3. 并发辩论冲突

**状态**: 已识别 | **优先级**: P1

#### 问题描述
多个辩论同时运行时，可能互相影响资源。

#### 影响
- API 限流
- 队列拥堵
- 数据库锁竞争

#### 解决方案

**队列管理**
- 使用 Bull 队列管理任务
- 全局并发限制（如 10 个并发辩论）
- 用户级限流（如每用户每分钟 5 轮）

**提供商限流**
- 按 AI 提供商分别限流
- OpenAI: 100 次/分钟
- Anthropic: 50 次/分钟

### 4. Realtime 连接断开

**状态**: 已识别 | **优先级**: P1

#### 问题描述
网络波动导致前端失去实时更新。

#### 解决方案

**断线重连**
- 指数退避策略（1s, 2s, 4s, 8s）
- 最大重试次数 5 次
- 失败后提示用户手动刷新

**状态同步**
- 记录最后可见轮次
- 重连后同步错过的数据
- 心跳检测（30 秒间隔）

#### 详细实现
见 `IMPLEMENTATION.md` 第 4 节

## 中优先级问题

### 5. 共识得分计算成本

**状态**: 已识别 | **优先级**: P2

#### 问题描述
每轮计算所有方案得分可能耗时较长。

#### 解决方案

**增量计算**
- 只计算变化的部分
- 支持/反驳分数单独计算
- 总分为加权和

**异步更新**
- 先存储发言
- 后台计算得分
- 通过 Realtime 推送更新

**缓存**
- 相同输入返回缓存结果
- 定期清理过期缓存

---

### 6. 观点抽取准确性

**状态**: 已识别 | **优先级**: P2

#### 问题描述
NLP 可能错误分类论据类型。

#### 解决方案

**AI 结构化输出**（推荐）
- 依赖 AI 自身输出结构化数据
- 最可靠、成本最低

**置信度阈值**
- 计算抽取置信度
- 低于 0.8 标记为待审核
- 用户可手动校正

**人工校验选项**
- 提供编辑界面
- 用户可修正分类
- 修正后重新计算得分

---

### 7. 用户干预滥用

**状态**: 已识别 | **优先级**: P2

#### 问题描述
用户可能过度干预影响辩论公正性。

#### 解决方案

**频率限制**
- 每轮最多 1 次干预
- 每次干预冷却时间 30 秒
- 每场辩论最多 10 次干预

**干预日志**
- 记录所有干预操作
- 可供审计
- 异常行为检测

**纯净模式**
- 用户可选择禁用干预
- 适合正式辩论场景

---

### 8. 多语言支持

**状态**: 已识别 | **优先级**: P2

#### 问题描述
用户问题可能是多语言的。

#### 解决方案

**语言检测**
- 使用 tinyld 检测语言
- 支持中文、英文、日文等

**多语言提示词**
- 为每种语言准备提示词模板
- JSON 键名保持英文
- 内容使用检测到的语言

## 决策记录

### 已确定决策

| 决策 | 选择 | 替代方案 | 理由 |
|------|------|----------|------|
| 队列实现 | Bull (Redis) | RabbitMQ, Kafka | 简单、与 Next.js 兼容好 |
| 结构化输出 | AI 自生成 | NLP 抽取 | 更准确、成本低 |
| 实时更新 | Supabase Realtime | WebSocket, SSE | 集成简单、无需额外服务 |
| 日志系统 | Pino | Winston | 性能更好、API 简洁 |
| 上下文管理 | 滑动窗口 + 摘要 | 完整历史 | 平衡成本与效果 |
