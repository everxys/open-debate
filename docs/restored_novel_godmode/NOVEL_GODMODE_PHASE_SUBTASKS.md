# 小说神作模式阶段内子任务模板

## 1. 目标

这份文档用于解决一个具体问题：

- 现在已经有“阶段”，但每个阶段内部仍然太容易发散

所以这份文档的职责不是重新定义阶段，而是把每个阶段拆成一组固定子任务，让运行时可以真正做到：
- 每轮只推进一个子任务
- 子任务完成前不切换
- 阶段内不横跳

这份文档应当和以下两份文档配合使用：
- `docs/NOVEL_GODMODE_MASTER_PROMPT.md`
- `docs/NOVEL_GODMODE_RUNTIME_PROMPT.md`

---

## 2. 总体规则

### 2.1 子任务的定位

子任务是“阶段内部的推进单元”。

层级关系必须固定为：
- 阶段 > 子任务 > 轮 > 回合

也就是说：
- 阶段决定当前在解决哪类问题
- 子任务决定当前在阶段内部处理哪一小块
- 一轮只推进一个子任务
- 一个回合只推进这一轮中的局部结论

### 2.2 子任务切换规则

只有满足以下条件，才允许进入下一个子任务：
- 当前子任务已经形成明确结论
- 当前子任务的产出已经落到指定文件
- 当前子任务没有关键未决项
- 当前子任务没有被判定为“明显平庸”

### 2.3 子任务的固定输出

每个子任务都应强制回答：
- 本子任务要解决什么
- 最终结论是什么
- 保留了什么
- 删除了什么
- 新增了什么
- 本子任务最弱的一笔是什么
- 是否允许进入下一个子任务

### 2.4 子任务的禁止事项

每个子任务都必须显式声明：
- 当前不解决什么
- 不允许提前做什么
- 不允许越到哪个后续阶段

## 12. 子任务和运行时 Prompt 的接线方式

后续实现时，运行时 Prompt 应直接读取这份文档对应的子任务结构。

推荐流程：
- 先确定当前处于哪个阶段
- 再确定当前阶段的哪个子任务未完成
- 再把该子任务内容注入运行时 Prompt
- 再限制本轮只处理这个子任务

这样运行时 Prompt 才不会只停留在“当前阶段”，而能真正细化到“当前阶段中的当前问题”。

## 13. 验收标准

如果这份子任务模板真正生效，应该能看到这些变化：

### 13.1 阶段内不再大范围跑题

AI 不再一轮里同时谈事件、人物、终局、章节。

### 13.2 中期轮数更有价值

中期轮数不再只是在“继续讨论”，而是逐个完成子任务。

### 13.3 每轮更容易产出有效文件更新

因为每轮任务更小、更具体，交付更容易落到文件上。

### 13.4 主持人总结更少，结构推进更多

模型会更多围绕当前子任务推进，而不是频繁进入泛化总结。

---

## 14. 结论

神作模式如果只有阶段，没有子任务，就仍然会在阶段内部失控。

真正稳定的做法必须是：
- 用阶段定义大问题
- 用子任务拆解当前问题
- 用运行时 Prompt 只推进当前子任务

只有这样，长轮次、高密度、多文件交付才不会变成高噪音低推进。
