# 小说神作模式运行时精简 Prompt 设计

## 1. 目标

这份文档不是新的母本 Prompt，也不是新的 workflow。

它只负责一件事：

- 定义“运行时真正喂给模型的精简版 Prompt 应该长什么样”

它的存在意义，是把：
- `docs/NOVEL_GODMODE_MASTER_PROMPT.md` 的上位规则
- `docs/NOVEL_GODMODE_WORKFLOW.json` 的机器约束

真正压缩成一份模型在每一轮都能稳定执行的运行时 Prompt。

---

## 2. 设计原则

运行时 Prompt 必须遵守以下原则：

### 2.1 只保留当前轮真正有用的信息

运行时 Prompt 不再复述整套创作哲学，也不再整份塞入完整素材库。

它只保留：
- 当前阶段
- 当前轮次
- 当前子任务
- 本轮允许做什么
- 本轮禁止做什么
- 本轮输出格式
- 本轮要更新哪些文件

### 2.2 母本 Prompt 不直接下发

`NOVEL_GODMODE_MASTER_PROMPT.md` 是总控母本，不是运行时正文。

运行时只应从母本中抽取：
- 当前阶段相关规则
- 当前子任务相关规则
- 当前所需的局部素材

而不是直接把母本整份复制给模型。

### 2.3 运行时 Prompt 必须短、硬、聚焦

运行时 Prompt 的核心目标不是“完整”，而是“稳定执行”。

它应该让模型一眼知道：
- 我现在在哪
- 我这一轮只干什么
- 我这一轮绝对不能干什么
- 我这一轮结束后应该留下什么产物

### 2.4 运行时 Prompt 必须优先抑制偷跑

模型最常见的问题不是“不会思考”，而是“顺手多做了下一阶段的事”。

所以运行时 Prompt 必须显式抑制：
- 提前收尾
- 提前定终局
- 提前进入下一阶段
- 把局部共识当成阶段完成

---

## 3. 三层材料如何分工

### 3.1 母本 Prompt 保留什么

保留在 `NOVEL_GODMODE_MASTER_PROMPT.md`：
- 创作总目标
- 创作哲学
- 点子分层规则
- 阶段总任务
- 原始素材库
- 质量闸门总标准

### 3.2 Workflow 保留什么

保留在 workflow preset：
- 最少轮数
- 输出预算
- 交付文件
- 完成条件
- 阶段切换规则

### 3.3 运行时 Prompt 保留什么

只保留：
- 当前阶段和当前轮次
- 当前阶段唯一目标
- 当前子任务
- 本轮允许事项
- 本轮禁止事项
- 当前要更新的文件
- 当前输出格式
- 当前最需要参考的局部素材

---

## 4. 运行时 Prompt 的标准结构

建议运行时 Prompt 固定为以下 8 个区块。

### 4.1 区块一：身份与模式

作用：
- 让模型知道自己处于“神作工厂模式”
- 但不重复整套母本哲学

保留内容：
- 这是长篇群像智斗创作
- 当前不是自由聊天，而是阶段化推进
- 默认不接受平庸内容

### 4.2 区块二：当前坐标

这是最关键的部分，必须强制存在。

至少包含：
- 当前阶段
- 当前轮次
- 当前子任务
- 当前阶段唯一目标
- 本轮只推进什么
- 本轮不解决什么

这是运行时 Prompt 的核心，不是附属信息。

### 4.3 区块三：本轮任务

只写本轮要完成的局部任务，不重复整个阶段所有目标。

例如：
- 只设计事件二和事件三的误导结构
- 只筛选本轮需要保留的 3 个中点子
- 只补角色 A 与角色 B 的镜像关系

要求：
- 任务必须具体
- 任务必须可验证
- 任务必须是当前轮就能推进的

### 4.4 区块四：本轮禁止事项

必须明确列出本轮绝对不能做的事。

例如：
- 不进入下一阶段总结
- 不提前定真 boss
- 不做章节级扩写
- 不输出最终收尾语气
- 不重复复述母本原则

这一块不是可选项，而是用来抑制模型偷跑的核心控制区。

### 4.5 区块五：本轮参考素材

只注入和当前任务最相关的局部材料。

例如：
- 当前阶段需要的 8 个候选点子
- 当前正在打磨的两个角色设定
- 当前正在设计的一个事件草案
- 当前要更新的文件摘要

禁止：
- 每轮重复注入完整素材库
- 每轮重复注入整份母本 prompt

### 4.6 区块六：当前文件任务

运行时 Prompt 必须明确告诉模型：
- 本轮要更新哪些文件
- 这些文件的目的是什么

例如：
- 更新 `final/08-five-major-events.md` 的“事件二误导结构”
- 更新 `final/10-relationships-and-betrayals.md` 的“宿敌镜像关系”

这样模型才会把输出和交付物绑定，而不是只停留在口头讨论。

### 4.7 区块七：输出格式

运行时 Prompt 必须继续收紧输出格式：
- 输出 Markdown
- 先写“当前坐标”
- 再写本轮结论
- 再写保留/删除/新增
- 再写本轮最弱项
- 再写下一轮继续打磨点

这部分不应依赖模型自行记忆。

### 4.8 区块八：结束提醒

只保留一句短提醒即可：

- 本轮目标是推进当前子任务，不是完成整个阶段。

不要再在末尾重复整套创作哲学。

---

## 5. 每轮必须保留的硬信息

无论处于哪个阶段，运行时 Prompt 每轮都必须保留以下硬信息：

1. 当前阶段
2. 当前轮次
3. 当前子任务
4. 当前阶段唯一目标
5. 本轮只推进什么
6. 本轮不解决什么
7. 当前要更新的文件
8. 输出格式要求

如果缺少这些信息，模型就更容易：
- 混淆阶段和轮次
- 提前进入下一阶段
- 忘记把讨论落到文件

---

## 6. 每轮必须删掉的冗余信息

运行时 Prompt 必须主动删掉这些东西：

### 6.1 整份母本哲学重复

不要每轮重复：
- 这是外星人作品
- 这是神作工厂模式
- 这是百万字圣经

这些只需保留极短版本即可。

### 6.2 整份原始点子库

不要每轮都把全部点子编号重新塞给模型。

只保留：
- 当前阶段相关点子
- 当前子任务相关点子
- 当前真正要比较和筛选的点子

### 6.3 整套阶段说明重复

不要每轮把全部阶段 1-9 都重复讲一遍。

只要告诉模型：
- 当前处于哪个阶段
- 当前阶段目标是什么
- 当前子任务是什么

### 6.4 与本轮无关的长篇世界观设定

如果当前在做事件设计，就不要整轮注入全量世界历史。
如果当前在做人物弧线，就不要整轮注入完整章节细纲。

---

## 7. 子任务驱动规则

运行时 Prompt 不应直接按“阶段”驱动，而应按“阶段中的子任务”驱动。

推荐机制：
- 一个阶段下有固定子任务列表
- 运行时每轮只绑定一个子任务
- 子任务完成后，才进入该阶段下一个子任务

这能明显减少：
- 同阶段内横跳
- 一轮里又谈结构又谈角色又谈终局
- 轮数很多但推进稀释

- 当前子任务：

-

-

## 9. 推荐和现有系统的接线方式

这份运行时 Prompt 文档后续应这样接线：

### 9.1 输入来源

运行时 Prompt 内容来源于三部分：
- 母本 Prompt 中当前阶段相关规则
- workflow 中当前阶段和轮次相关规则
- 当前阶段下当前子任务的局部素材

### 9.2 不再直接读取整份母本

实现时不应把 `NOVEL_GODMODE_MASTER_PROMPT.md` 整份拼进运行时 system prompt。

正确方式是：
- 先裁剪出当前阶段相关内容
- 再裁剪出当前子任务相关内容
- 最后拼成运行时精简版

### 9.3 与现有 workflow 能力的关系

现有能力已经足够支撑第一步落地：
- `phaseMachine.phases[].minRounds`
- `promptPolicies.outputBudget`
- `deliverables.requiredFiles`
- `transitionRules.finalization`

后续再补：
- `phaseMachine.phases[].subtasks`
- `promptPolicies.runtimePromptMode`
- `roleWritingAssignments`

## 10. 验收标准

如果运行时 Prompt 设计成功，应该出现这些变化：

### 10.1 阶段和轮次不再混淆

模型每轮都能稳定先报当前坐标，不再把“当前轮”误当“当前阶段”。

### 10.2 中期讨论强度明显提升

第 10 几轮不再过早进入主持人确认和总结，而是继续围绕子任务打磨事件、诡计、关系和结构。

### 10.3 输出更聚焦

每轮输出明显围绕当前子任务，不再同时处理太多跨阶段问题。

### 10.4 交付更稳定

模型更容易把本轮推进落到具体文件，而不是只做口头讨论。

### 10.5 Prompt 负担明显下降

运行时不会再每轮重复消化整份母本和完整素材库，输出稳定性会提高。

---

## 11. 结论

运行时 Prompt 的正确方向不是“把母本缩短一点”，而是彻底分层：

- 母本保留在上位
- 运行时只保留当前执行所需信息
- workflow 继续负责硬规则

只有这样，神作模式才不会因为 Prompt 过长而失控，也不会因为信息过多而变成低密度重复讨论。
